# Working in this fork (for coding agents)

This checkout is `ttbeast10/optio-fork`, a fork of `jonwiggins/optio`
(upstream). `AGENTS.md` describes the code and applies in full. This file
is about the branches. The long version, with every command, is
`fork/README.md` on the branch `fork/overlay`.

## Which branch is which

- `main` is a copy of upstream's `main`. Never commit to it. Start every
  change from it.
- `feat/…` / `fix/…` are topic branches: one change each, one upstream pull
  request each.
- `fork/overlay` holds the fork's own files: `fork/` and `deploy/airgap/`.
- `fork/combined` is `main` + every topic branch in `fork/branches.txt` +
  `fork/overlay`. It is generated by `fork/integrate.sh`. Never commit to
  it; images and bundles are built from it.

Before you change anything, find out where you are: `git branch --show-current`.

## Rules

- Code changes go on a topic branch started from `origin/main`
  (`fork/new-topic.sh <type>/<name>` from a `fork/overlay` checkout makes
  one in its own worktree). If asked to fix something seen in
  `fork/combined`, fix it on the topic branch that owns that code, not on
  `fork/combined`.
- A topic branch never touches `fork/` or `deploy/airgap/`. Those change
  only on `fork/overlay`.
- One change per branch. Do not add an unrelated fix to an existing topic
  branch: it would end up in that branch's upstream pull request.
- Never push to `jonwiggins/optio`. Never merge or close a pull request
  there. `main` only moves by `fork/sync.sh`.
- A rewritten branch is pushed with `--force-with-lease`, never `--force`.
- Run `pnpm check:push` before pushing a topic branch and let the hooks run.
- Upstream pull requests are opened with `fork/pr.sh <branch>`, which uses
  `fork/pr/<branch with / as ->.md` (line 1 the title, then the description
  under upstream's template headings). Open one only when the owner asks.
  In the description, say what was and was not run locally.
- After changing a topic branch that is in `fork/branches.txt`, the combined
  branch is stale until `fork/integrate.sh --push` runs. Say so in your
  report if you did not run it.
- Two topic branches that merge cleanly but break each other get a patch in
  `fork/fixups/`; the upstream pull request merged second must carry it.

## Ask the owner before

Deleting a branch, changing `fork/branches.txt` for a reason other than a
new or merged branch, opening or updating an upstream pull request, or
deploying over an install you did not create.
